# 智碳 MVP 技术设计

状态：开发基线提案；依据已讨论的产品方向制定，尚未经 SketchUp 实机验证。
日期：2026-10-25。用户原始清单实际为 14 项；不补造第 15、16 项。

## 目标与范围

在 SketchUp 中完成深圳项目的太阳辐射分析、多层构造编辑与可追溯结果展示。
首发 Windows，目标 SketchUp 2024–2026，并兼容 2021。
现有仓库是 React + TypeScript + Vite 模板，不是已完成的插件。

MVP 包括：场景提取、模型体检、城市与真北、经授权 EPW 导入、多层构造、
快速辐射预览、Radiance 专业计算接口、四向窗墙比、有限规则校核、PDF 报告。
不包括：完整建筑全年能耗、HVAC、所有城市所有规范、绿建等级自动认证。
室内采光及年度分析列入后续阶段，不因预留接口而宣称已实现。

## 方案取舍

1. 纯 Ruby：宿主接口方便，但计算阻塞和大模型性能风险高，不作为计算主架构。
2. 全云端：利于集中算力，但上传延迟、模型隐私和网络依赖不利于即时联动。
3. Ruby + React + 本地独立计算服务：推荐基线；宿主、界面、计算隔离，后期可增加云任务。

以上为技术建议，不把操作系统优先级、性能数字和库版本表述为用户已确认的验收承诺。

## 选型与部署

- 宿主：Ruby API、HtmlDialog、Observers；只在允许的宿主线程访问模型。
- 界面：沿用当前 React/TypeScript；能力检测后再确定旧版 HtmlDialog 的构建目标。
- 本地服务：C++17，CMake，CPU 射线计算；优先验证 Embree 的平台、许可及分发可行性。
- 精算：Radiance 独立进程；固定已验证版本与参数，安装包保留许可证。
- 气象：EPW 离线导入；真实数据经来源、许可和质量检查后才能内置。
- 规范：版本化规则数据；不使用未经审核的示例阈值产生合规结论。
- 报告：HTML 模板交给独立报告进程输出 PDF，不依赖 HtmlDialog 打印。
- 后续能耗：另建热区、运行计划与设备模块后接 EnergyPlus。

当前云端为 Linux，可做界面、协议、解析器和算法测试；不能替代 Windows SketchUp 验证。
后续引入工具时必须保持 TLS、签名、校验和验证，不以关闭验证解决安装问题。

## 领域模型

外观材质 Appearance、物理材料 Material、层 Layer、构造 Construction 分离。
SketchUp 材质只提供默认构造关联；面或构件可覆盖。同一外观允许对应不同构造。
模型属性字典保存语义和关联；结果缓存放模型外的用户数据目录，不写入原始纹理。

面标识由模型标识、实例路径和面标识组成；共享定义的多个实例不可共用结果身份。
输出世界坐标（米）、三角形、法线、面积、角色及构造引用；镜像、非均匀缩放需要正确处理。
外墙、窗、屋面、遮阳、障碍物必须可确认；缺失语义时允许预览，但阻止依赖该语义的合规结论。

## 计算及显示契约

快速预览：单时刻直射遮挡与投影，后续增加近似天空散射。初版直射预览必须明确标注“仅直射”。
专业计算：Radiance 计算约定天空与材料下的辐射；采光使用独立光度学流程。
U 值：只对明确适用的一维串联构造使用 U = 1 / (Rsi + Σ d/λ + Rse)。
空气层、热桥、复杂幕墙和通风构造不可偷偷套用该公式。

结果必须区分 W/m²、kWh/m²、lux、W/(m²·K)，不得由辐射直接推导表面温度或建筑节能率。
没有真实 EPW 时可展示标明“合成演示”的数据，不生成真实深圳分析结论。
真实典型年数据不称为实时天气；时间统一保存当地标准时与时区，不静默引入夏令时。

Observers 只记录变化，在安全时机合并。建议防抖初值 500 ms；拖动期间降级或暂停精算。
每次场景改变递增 revision；旧任务结果不得覆盖新模型。几何变化可能影响远处阴影。
进度、取消、失败、过期状态均可见；不能以插值颜色伪装精算结果。

2024–2026 验证 Overlay 路径；2021 验证 Tool#draw 兼容路径。
必要时生成独立分析组，禁止覆盖原材质；结果组必须排除出后续场景提取。

## 规范与报告

每条规则保存标准编号、版本、条款、适用条件、单位、比较方式、阈值来源和审核状态。
状态：pass、fail、insufficient_data、not_applicable、needs_review。
只有依据明确的 fail 标红；缺输入不得显示通过。建议值与法定限值分开。
首个规则包建议深圳公共建筑；具体条款和现行版本须由专业人员依据正式来源审核。
报告保留场景、气象、规则、引擎、参数及结果版本，并列出未校核项和人工覆盖。

## 验收与决策门

P0 必须证明四版本能加载、导出、调用本地进程并显示结果。
Radiance 必须用同场景独立运行结果验证导出、单位和参数，而非仅证明命令能启动。
性能在固定硬件、三角形数、测点数与质量参数下测量；1–3 秒预览只是候选目标。
未通过矩阵的平台不得宣称支持；没有实测依据不得承诺统一百分比精度。
